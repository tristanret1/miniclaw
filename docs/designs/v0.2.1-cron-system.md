# Design: Cron System (v0.2.1)

> Iteration: v0.2.1
> Date: 2026-03-14
> Status: Implemented

## Goal

为 miniclaw 引入定时任务系统，让 bot 可以按计划自动执行任务并将结果发送到 Discord 频道。
典型用例：每天早上发送滑雪场雪况预报、定期检查 GitHub PR、定时提醒等。

## Background

openclaw 的 cron 系统是一个完整的生产级调度器，包含：
- 三种调度模式（一次性 `at`、周期性 `every`、cron 表达式）
- 文件存储（JSON）、并发锁、指数退避、失败告警
- 多种投递方式（announce、webhook）
- 独立 agent session 执行

miniclaw 需要一个**简化版本**，符合项目"minimal"的理念：
- SQLite 存储（与现有 memory/sessions 一致）
- asyncio 调度（复用现有事件循环）
- Discord 频道投递（核心场景）
- Agent 对话执行（复用现有 Claude API 流程）

## Architecture

```
miniclaw/

```

## 架构调整：独立 Agent Session

### 问题：为什么不能直接用 `get_reply()`

当前 `get_reply()` / `get_reply_stream()` 有以下耦合：

| 耦合点 | 现有行为 | cron 需求 |
|--------|---------|----------|
| Session 持久化 | 每轮 append 到 sessions.db + 内存缓存 | 临时执行，不污染用户对话 |
| History 加载 | 从 DB 延迟加载，pair-aware windowing | 无历史，每次从零开始 |
| System prompt | 固定使用全局 `SYSTEM_PROMPT` | 可能需要注入任务上下文 |
| Auto-flush | 历史超 80k chars 触发 memory flush | 不需要，执行完即丢弃 |
| 错误恢复 | 400 sanitize + retry | 同样需要，但基于临时 messages |

### 解决方案：`run_isolated_turn()`

在 `bot/claude.py` 中新增一个独立执行函数，**不碰**现有 session 系统：

```python
async def run_isolated_turn(
    message: str,
    *,
    system_prompt: str | None = None,
    model: str | None = None,
    max_rounds: int = 10,
    timeout: float = 300,
) -> str:
    """Run a single isolated agent turn with tool use.

    - No session persistence (ephemeral messages list)
    - No history loading
    - No auto-flush
    - Custom system prompt + model support
    - Full tool-use loop (same as get_reply_stream)
    - Returns final text response
    """
```

#### 执行流程

```
run_isolated_turn(message, system_prompt=...)
    ↓
Build ephemeral messages: [{"role": "user", "content": message}]
    ↓
┌─ Tool-use loop (max N rounds) ──────────────────────┐
│  _call_claude_isolated(messages, system_prompt)      │
│      ↓                                               │
│  if stop_reason == "tool_use":                       │
│      execute tools (same handle_tool_call)           │
│      append assistant + tool_result to messages      │
│      continue loop                                   │
│  else:                                               │
│      return extracted text                           │
└──────────────────────────────────────────────────────┘
    ↓
Messages list is discarded (GC)
```

#### 与现有代码的关系

```
claude.py
├── _build_request_body(messages, stream)      # 现有，硬编码 SYSTEM_PROMPT
├── _build_request_body_custom(messages, system_prompt, stream)  # 新增
├── _call_claude(messages)                     # 现有，用于 tool loop + flush
├── _call_claude_isolated(messages, system_prompt)  # 新增，用自定义 prompt
├── get_reply_stream(session_key, content)     # 现有，用户对话
├── get_reply(session_key, content)            # 现有，non-streaming wrapper
└── run_isolated_turn(message, ...)            # 新增，cron/独立任务
```

**关键决策**：`run_isolated_turn()` 复用 `handle_tool_call()`（tools 不变），
复用 `_get_http_client()`（连接池共享），复用 `_get_access_token()`（认证共享），
但**不**碰 `_sessions`、`append_message()`、`_run_flush()` 这些 session 相关状态。

#### `_build_request_body_custom()` 实现

```python
def _build_request_body_custom(
    messages: list[dict],
    system_prompt: str,
    stream: bool = False,
) -> dict:
    """Like _build_request_body but with custom system prompt."""
    body = {
        "model": CLAUDE_MODEL,
        "max_tokens": 4096,
        "system": system_prompt,
        "messages": messages,
        "stream": stream,
    }
    if TOOLS_ENABLED:
        body["tools"] = ALL_TOOLS
    return body
```

## Per-Job 上下文配置

### 对比 openclaw

| 能力 | openclaw | miniclaw v0.2.1 |
|------|---------|-----------------|
| 独立 agent 身份 | `agentId` → 不同 workspace (SOUL.md, skills) | `context` 字段追加额外指令 |
| Session 模式 | `sessionTarget: "main" \| "isolated"` | `session_mode: "isolated" \| "persistent"` |
| 模型覆盖 | `payload.model` + allowlist | `model` 字段，直接覆盖 |
| 工具过滤 | per-agent skills filter | 不做（全部工具可用） |
| 对话历史 | main = 跨次保留, isolated = 每次从零 | persistent = 跨次保留, isolated = 每次从零 |

openclaw 用 `agentId` 解析出一整套独立 workspace（SOUL.md、IDENTITY.md、skills/、memory/），
本质是**多 agent 架构**。miniclaw 是单 bot，不需要这层抽象，用 `context` 字段达到类似效果。

### `session_mode` 详解

#### `"isolated"`（默认）

- 每次执行都是全新的 messages 列表
- 不持久化对话历史
- 执行完即丢弃
- 适用场景：雪况预报、提醒、报告生成

```
Run 1: messages = [user] → tool loop → response → 丢弃
Run 2: messages = [user] → tool loop → response → 丢弃
```

#### `"persistent"`

- 使用 session key `cron:{job.id}` 调用现有 `get_reply()`
- 对话历史持久化到 sessions.db，跨次保留
- 受 `HISTORY_CHAR_BUDGET` 限制，自动 windowing
- 适用场景：状态追踪、diff 对比（"上次有 3 个 PR，现在变成 5 个了"）

```
Run 1: messages = [user] → response → 存入 sessions.db
Run 2: messages = [历史...user] → response → "与上次相比，新增了 2 个 PR"
```

### `context` 详解

额外指令文本，追加到全局 `SYSTEM_PROMPT` 后面，形成 per-job system prompt：

```python
# 构建 per-job system prompt
job_system_prompt = SYSTEM_PROMPT
if job.context:
    job_system_prompt += f"\n\n---\n\n[Scheduled Task: {job.name}]\n{job.context}"
else:
    job_system_prompt += f"\n\n---\n\n[Scheduled Task: {job.name}]"
```

典型用法：

```json
{
    "name": "daily-snow-forecast",
    "context": "你是一个滑雪气象分析师。用简洁的中文汇报，重点关注：降雪量、雪质（粉雪/湿雪）、风速、能见度。如果 24h 降雪 > 15cm 且温度 < -5°C，标注为 POWDER DAY。",
    "payload": "查询 cypress 和 whistler 的雪况预报。"
}
```

这样每个 cron job 可以有完全不同的"人格"和行为指令，不需要多 agent 架构。

### `model` 详解

覆盖全局 `CLAUDE_MODEL`，让不同 job 使用不同模型：

```json
{
    "name": "simple-reminder",
    "model": "claude-haiku-4-5-20251001",
    "payload": "提醒用户去开会"
}
```

- 空字符串 = 使用全局 `CLAUDE_MODEL`
- 简单任务（提醒）用 Haiku 省 token
- 复杂任务（代码分析）用 Sonnet/Opus

### `_execute_job` 更新后的流程

```python
async def _execute_job(self, job: CronJob):
    async with self._sem:
        # 1. Build per-job system prompt
        system_prompt = SYSTEM_PROMPT
        task_header = f"\n\n---\n\n[Scheduled Task: {job.name}]"
        if job.context:
            system_prompt += task_header + "\n" + job.context
        else:
            system_prompt += task_header

        # 2. Resolve model
        model = job.model or None  # None = use global default

        # 3. Execute based on session_mode
        if job.session_mode == "persistent":
            session_key = f"cron:{job.id}"
            reply = await get_reply(
                session_key, job.payload,
                system_prompt_override=system_prompt,
                model_override=model,
            )
        else:  # "isolated"
            reply = await run_isolated_turn(
                message=job.payload,
                system_prompt=system_prompt,
                model=model,
                max_rounds=10,
                timeout=300,
            )

        # 4. Deliver to Discord
        channel = self._bot.get_channel(int(job.channel_id))
        for i in range(0, len(reply), 2000):
            await channel.send(reply[i : i + 2000])
```

## 调度引擎：`bot/cron.py`

### 核心组件

```python
class CronScheduler:
    """asyncio-based cron scheduler with concurrent execution."""

    def __init__(self, bot: discord.Client):
        self._bot = bot
        self._timer_handle: asyncio.TimerHandle | None = None
        self._ticking = False
        self._sem = asyncio.Semaphore(CRON_MAX_CONCURRENT)  # 并发限制

    async def start(self):
        """在 bot on_ready 后调用，启动调度循环。"""

    async def stop(self):
        """优雅停止。"""

    def _arm_timer(self):
        """计算下一个到期任务，设置 asyncio timer。"""

    async def _on_tick(self):
        """Timer 到期回调：并发执行所有到期任务，重新 arm。"""
        due_jobs = self._load_due_jobs()
        self._mark_running(due_jobs)
        results = await asyncio.gather(
            *[self._execute_job(job) for job in due_jobs],
            return_exceptions=True,
        )
        self._apply_results(due_jobs, results)
        self._arm_timer()

    async def _execute_job(self, job: CronJob):
        """执行单个任务（受 Semaphore 限制），独立 agent session。"""
        async with self._sem:
            reply = await run_isolated_turn(
                message=job.payload,
                system_prompt=...,
                max_rounds=10,
                timeout=300,
            )
            channel = self._bot.get_channel(int(job.channel_id))
            await channel.send(reply)
```

### 调度逻辑

1. **启动时**：加载所有 enabled 任务，计算 `next_run_at`，arm timer
2. **Timer 精度**：最大 60s 唤醒一次（防止时钟漂移），最小 2s 间隔
3. **到期检测**：`now >= next_run_at` 的任务即为到期
4. **并发执行**：所有到期任务通过 `asyncio.gather()` 并发执行，每个 job 一个独立 agent session
5. **并发限制**：`asyncio.Semaphore(CRON_MAX_CONCURRENT)` 控制最大并发数（默认 5）
6. **System prompt**：注入任务上下文到 system prompt（job name + 基础 SYSTEM_PROMPT）
7. **结果投递**：将 Claude 回复发送到 `job.channel_id` 指定的 Discord 频道
8. **执行后**：更新 `last_run_at`、`last_status`，计算下一次 `next_run_at`
9. **错误处理**：记录 `consecutive_errors`，指数退避（30s → 1m → 5m → 15m → 1h）
10. **一次性任务**（`at`）：执行成功后自动 `enabled = False`

### Schedule 类型解析

```python
def compute_next_run(schedule_type: str, schedule_value: str, timezone: str, after: float) -> float:
    """计算下一次执行时间。"""
```

| Type | Value 示例 | 说明 |
|------|-----------|------|
| `every` | `"30m"`, `"2h"`, `"1d"` | 固定间隔，从上次执行开始计算 |
| `cron` | `"0 8 * * *"` | 标准 5-field cron 表达式 |
| `at` | `"2026-03-15T08:00:00"`, `"+20m"` | 一次性，ISO 时间或相对偏移 |

### 执行流程

```
Timer fires
    ↓
Load due jobs (next_run_at <= now AND enabled)
    ↓
Mark all due jobs running (prevent re-trigger on next tick)
    ↓
asyncio.gather(*[_execute_job(job) for job in due_jobs])
    ↓                          ↓                        ↓
┌─ Job A (isolated) ─┐  ┌─ Job B (isolated) ─┐  ┌─ Job C ──┐
│ Semaphore.acquire() │  │ Semaphore.acquire() │  │ waiting  │
│ run_isolated_turn() │  │ run_isolated_turn() │  │   ...    │
│ ├─ tool loop        │  │ ├─ tool loop        │  │          │
│ ├─ exec snow.py     │  │ ├─ exec gh pr list  │  │          │
│ └─ return text      │  │ └─ return text      │  │ acquire  │
│ Send to Discord     │  │ Send to Discord     │  │ run ...  │
│ Update job state    │  │ Update job state    │  │          │
└─────────────────────┘  └─────────────────────┘  └──────────┘
    ↓
Re-arm timer for next due job
```

每个 job 拿到独立的 ephemeral messages 列表，互不干扰。
Semaphore 控制不会同时有太多 Claude API 调用。

简单提醒不需要 Sonnet，用 Haiku 省 token。

## 依赖

- `croniter>=2.0` — cron 表达式解析（轻量级，纯 Python）
- 无其他新依赖（asyncio、SQLite 均为标准库）

## Scope（v0.2.1 不做的）

- ❌ Webhook 投递（只支持 Discord 频道）
- ❌ 失败告警通知（仅 log + 退避）
- ❌ Run log 持久化（仅更新 job 状态字段）
- ❌ cron_update 工具（先删后建）
- ❌ Web UI / Dashboard
- ❌ 自定义 per-job tools subset（全部工具可用）
- ❌ 多 agent 架构（agentId，独立 workspace）
- ❌ Session 过期策略（persistent 模式不自动清理，受全局 HISTORY_CHAR_BUDGET 约束）

这些留给后续迭代。
